# 合约交易解码（`contract_decode_tx_input`）

以下约定在**用户明确要求解析 / 解码某笔链上合约交易**时适用；与泛泛问答、仅查块高/余额等场景无关。

## 触发条件（须同时满足再走路径）

- 用户意图是：**解释这笔交易在合约层做了什么**、**解析 input**、**对应哪个协议调用**等，而不仅是「查哈希是否存在」。
- 已拿到或可规范化出 **交易哈希**（以太坊常见带 `0x` + 64 位 hex；波场常见为 **不带 `0x` 的 64 位 hex**）。**不要求用户必须声明链种**。
- 环境中已配置并可用 **`CONTRACT_DECODE_SCRIPT_PATH`** 时，才调用工具 **`contract_decode_tx_input`**；若当前对话未挂载该工具或配置缺失，**不得编造**解码结果，仅可基于节点原始数据做有限说明。

## 链种推断（用户未说明时）

- **哈希以 `0x` 开头**（大小写不敏感）：**优先按以太坊**处理；`eth_getTransactionByHash` 的 `params` 须保留 **`0x` 前缀**。
- **哈希不以 `0x` 开头**：**优先按波场**处理；调用波场钱包 API 时通常使用 **无 `0x` 的 64 位十六进制** txId（以节点文档为准）。
- **双链探测**：若用户未说明链种且仅凭形态不确定，或优先链查询返回空 / 明显无效，在**已配置对应节点工具**的前提下，可**依次尝试另一条链**（例如先 ETH 再 TRON，或先 TRON 再 ETH），**以「哪条链的节点返回了完整交易对象」为准**确定链种，再进入后续步骤。两条都无有效交易时，如实告知并停止解码脚本。

## 禁止 / 不必调用解码工具的情况

- 用户未表达「解析、解码、说明合约调用」类需求（例如只要最新块、账户 TRX 余额、跑 SQL 报表）。
- 节点查询在**已尝试的链上**均**无此交易**或持续失败时，不要继续调用解码脚本硬解。
- 某条链未配置节点工具（如无 `ETHEREUM_JSONRPC_URL`）则**不要假装**已查询该链；仅对已配置的节点做双链尝试。

## 推荐执行顺序（固定流程）

1. **先用节点工具按哈希拉取交易事实**（链种按上一节推断，必要时双链尝试）  
   - **波场**：`tron_node_request`，`target` 按需选 `full` 或 `solidity`；常见如 `/wallet/gettransactionbyid`（请求体含 `value` 为 txId 等，字段名以节点文档为准），必要时再调 `/wallet/gettransactioninfobyid` 补全收据、日志。  
   - **以太坊（及兼容链）**：`ethereum_jsonrpc`，例如 `eth_getTransactionByHash`，`params` 为 `["0x + 64位hex"]`（若用户给的是无 `0x` 的 hex，调用前补上 `0x`）；需要事件/状态时再调 `eth_getTransactionReceipt` 等。

2. **从节点返回中确定「合约侧」地址作为脚本的 `address` 参数**  
   - 优先使用**被调用合约**地址：以太坊交易对象中的 **`to`**；波场需根据 `raw_data.contract` / 返回结构取**主合约或目标合约**地址（不同接口字段名可能为 `contract_address`、`owner_address` 等，**以实际 JSON 为准**）。  
   - 若为**纯 TRX 转账**且无合约 `to`，通常**不适用**合约解码脚本；应向用户说明并仅解读转账事实。

3. **调用 `contract_decode_tx_input`**（若脚本实际仅支持波场，而链上已确认为以太坊，则勿期待脚本一定成功；可主要依据 `eth_*` 返回向用户说明，并如实说明脚本适用范围。）  
   - `tx`：**64 位十六进制、无 `0x`**（若用户或节点侧为带 `0x` 的哈希，调用本工具前去掉前缀）。  
   - `address`：上一步得到的合约相关地址，格式需与 **AI-ContractParser 脚本**要求一致（如波场 Base58 `T...` 或脚本支持的 hex）。  

4. **分析与答复**  
   - 以**节点返回**为链上事实依据；以**解码脚本 stdout** 的结构化内容为合约语义依据。  
   - **严格按脚本输出中的字段与层级**归纳，不要臆造脚本未给出的函数名、金额或协议名。  
   - 若脚本报错或输出不完整，**如实引用**错误信息，并说明可能原因（节点数据不全、合约未在解析器协议库中、参数地址不匹配等）。  
   - 最终用**自然中文**先结论后细节；区分「链上可验证事实」与「解析器推断」。

## 与「只查库表」的关系

- 解码流程**不替代**业务库查询；若用户还需要 JustLend / 索引库等**落库数据**，在完成或并行完成链上事实与解码后，再按 `agent_database_schema.md` 规则查表。
